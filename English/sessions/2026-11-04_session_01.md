# Session Log: A Tour of Go: Packages, variables, and functions

## 1. Excerpt Studied
> Every Go program is made up of packages. Programs start running in package `main`. In Go, a name is exported if it begins with a capital letter. When importing a package, you can refer only to its exported names; any unexported names are not accessible from outside the package.
>
> Functions can take zero or more arguments, and their parameters declare types after the variable name. A function can return any number of results. Go's return values may be named. If so, they are treated as variables defined at the top of the function. A return statement without arguments returns the named return values; this is known as a "naked" return. Naked return statements should be used only in short functions, as they can harm readability in longer programs.
>
> The `var` statement declares a list of variables, and variables declared without an explicit initial value are given their zero value. Inside a function, the `:=` short assignment statement can be used in place of a `var` declaration with implicit type inference. Outside a function, however, every statement begins with a keyword, and the `:=` construct is not available.

## 5. Review Cards Added
### Vocabulary (5 words)
1. `exported name` (noun): An identifier starting with an uppercase letter that is accessible outside its defining package. (패키지 외부 접근 가능한 대문자 식별자)
2. `naked return` (noun): A return statement without explicit arguments that returns the current values of named return variables. (이름 붙은 반환값의 인수 없는 return문)
3. `zero value` (noun): The default value automatically assigned to a variable declared without an explicit initial value. (명시적 초기화 값 없는 변수의 기본값)
4. `short assignment statement` (noun): A syntactic construct (`:=`) used inside functions to declare and initialize variables with inferred types. (함수 내 타입 추론 단축 변수 선언문)
5. `type inference` (noun): The compiler's automatic deduction of an expression's data type from the assigned value. (타입 추론)

### Idiomatic Expressions (2 expressions)
1. `in place of`: Used to denote syntactic substitution or a more concise alternative without semantic change. (~를 대신하여 / 대체하여)
2. `harm readability`: Used in Go guidelines to strongly discourage patterns that impede code clarity (equivalent to SHOULD NOT). (가독성을 해치다)
